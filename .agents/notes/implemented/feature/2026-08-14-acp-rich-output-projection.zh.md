# Agent Note: ACP rich 输出投影

Status: implemented

[English](2026-08-14-acp-rich-output-projection.md) | 中文

## 问题

ACP 桥接层的 committed 消息投影适合自动化父 agent，因为它绝不会公开部分提供方输出或被丢弃的尝试。AionUi 等交互式 ACP 客户端使用同一套标准协议，但需要增量回答文本、推理、工具状态和计划状态，以便在 agent 轮次运行时进行展示。如果没有显式投影，即使权威会话日志已经记录所需事件，这些客户端也只能显示最终答案。

恢复原来的编辑器桥接层还会一并恢复无关的产品职责：会话浏览、命令、配置选择器、面向人类的信息征集、编辑器元数据和工具专用渲染策略。该交互用例只需要实时传输一小部分事件，而不需要第二套 Harness UI。

## 决策

`@deepseek-ai/dsh-acp` 提供连接级 `output` 配置，取值为 `committed` 或 `rich`。`committed` 仍是默认值并保留自动化行为。`rich` 将文本增量作为 `agent_message_chunk` 发出，将推理增量作为 `agent_thought_chunk` 发出，将工具调用及其结果作为 ACP 工具调用生命周期更新发出，并将 `todo/write` 快照作为 ACP 计划发出。流式增量发出后，它不会重复发送已提交的 assistant 文本。

所有投影值都来自 `session/event`，因此面向模型的活动仍可从持久日志重建。工具执行继续留在 Harness 内。ACP 卡片采用通用投影：常见工具名称决定 ACP 类别，常见参数字段提供简洁标题，解析后的参数成为 `rawInput`，面向模型的文本或图像引用以及持久元数据成为 `rawOutput`。桥接层不挂载工具渲染器，也不新增终端、diff、位置、标题、用量、命令、模式、会话导航或信息征集支持。

`@deepseek-ai/dsh-acp-demo` 通过 `acpOutput` 转发该投影。交付的 ACP 叶节点读取 `DSH_ACP_OUTPUT`，默认值为 `committed`；`scripts/aionui-acp.mjs` 则以 `rich` 启动该叶节点，除非调用方已经选择其他值。启动器通过 Node 和 `tsx` 直接调用源码 bin，使 stdout 保持只承载以换行分隔的 JSON-RPC。

ACP 桥接测试会锁定默认 committed 输出，以及 rich 文本、推理、工具、失败和计划更新。无密钥 `todo-write` ACP 快照使用 rich 输出运行组装后的示例，并记录推理、工具调用生命周期、计划快照、工具结果和最终答案帧。启动器冒烟测试在没有模型凭据的情况下执行 ACP `initialize` 和 `session/new`。

先前的[仅面向自动化的 ACP 决策](../simplification/2026-07-23-acp-automation-only-protocol.md)仍是默认投影和所有省略产品界面的权威说明。本决策只是针对标准实时更新的一项狭窄显式例外，并非重新回到由编辑器拥有 UI 的方案。

## 考虑过的替代方案

**将 rich 输出设为默认值。** 不予采用，因为自动化父 agent 依赖完整的 committed 文本；未经显式选择，它们不应收到部分或被丢弃的提供方输出。

**恢复原来的通用编辑器桥接层。** 不予采用，因为会话管理、命令、模式、配置、面向人类的提问和工具专用展示仍属于产品宿主，而非该传输层。

**添加 AionUi 专用插件或私有 wire 协议。** 不予采用，因为 AionUi 已经消费标准 ACP 更新，而且该投影对任何兼容的交互式客户端都有用。客户端品牌专用协议会重复类型化 ACP 消息，并使 Harness 包与单一 UI 耦合。

**由客户端从持久化数据中读取进度。** 不予采用，因为这需要共享文件系统访问、轮询、持久格式知识和会话 id 对账，而 ACP 已经提供实时通知通道。

## 结果

除非部署选择 `rich`，否则自动化行为保持不变。交互式 ACP 客户端可以通过标准消息渲染实用的实时轮次，同时不会取得工具执行或 Harness 会话管理的所有权。桥接层在 rich 模式下会携带更多事件和逐调用状态，其通用工具卡有意省略工具专用 diff、终端和位置。提供方重试可能在步骤提交前通过 rich 模式公开部分文本；要求输出不混入失败尝试的部署继续使用默认 committed 投影。
